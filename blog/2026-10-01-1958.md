# make events が filter_map で落ちた

`make events` が `csv2yaml.rb:188` の `NoMethodError` で止まった。メッセージは `undefined method 'filter_map'`。スキップ表示のあとなので、CSV の選び方を疑いたくなるが、落ちている箇所はそこではない。

この Mac の `ruby` は `/usr/bin/ruby` の 2.6.10 だった。`Enumerable#filter_map` は Ruby 2.7 で入ったメソッドで、2.6 にはない。README は「Ruby はシステムのものを使う」と書いてあり、Makefile も素の `ruby` を呼ぶ。rbenv には 3.4.7 が入っているが、`~/.rbenv/shims` は PATH に無く、zsh の設定にも `rbenv init` が無い。だから `make` はシステムの 2.6 を使う。

その行は 2026-09-05 の `46f1878`（イベント名の重複をエラーにする変更）で入った。重複が無いときは `group.size < 2` で飛ばすので、2.6 でもそこまでは進む。今回は 2026 年の CSV に同名が 2 行あり、重複メッセージを組み立てる直前で落ちた。

Ruby 3.4.7 で同じ変換の検査だけ走らせると、クラッシュの代わりに次の検証エラーが出る。

`techイベントデータ - 2026.csv`: イベント名が重複しています: OSINT.JP Conference 2026（行 156, 157、どちらも 2026-10-17）

冒頭の「2027 (1).csv をスキップ」は、同じ年のより新しい CSV があるときの通常の警告で、今回の例外とは別だ。2027 年の採用ファイル側に検証エラーは無かった。

直すなら、2.6 でも動く書き方に戻すか、実行する Ruby を 2.7 以上に揃える。どちらにしても、重複行が残っているあいだ `make events` は YAML を出さずに止まる。
