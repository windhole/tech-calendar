# make を rbenv の Ruby 4.0.7 にした

先に `make events` が落ちたのは、システムの Ruby 2.6.10 に `filter_map` が無いせいだった。直す方針は、スクリプトを 2.6 向けに戻すのではなく、rbenv の最新安定版で動かすことにした。2026-10-01 時点の MRI は 4.0.7 で、手元の rbenv には 3.4.7 までしか無かったので、`rbenv install 4.0.7` で入れた。

バージョンはリポジトリの `.ruby-version` に固定する。Makefile の `events` / `check` / `clean` は `rbenv exec ruby` を呼ぶ。PATH に shims が無くても、このディレクトリでは 4.0.7 になる。判断は ADR-0020 に書いた。ADR-0006 と ADR-0011 にあった「システム Ruby で足りる」は、ここが置き換える。

確認は `rbenv exec ruby -v` が 4.0.7 になることと、`make events` / `make check` が完走すること。`filter_map` の `NoMethodError` は出なかった。変換はより新しい `data/techイベントデータ - 2026 (1).csv`（159 件）と `2027.csv`（14 件）を使い、`public/events_2026.yaml` と `public/events_2027.yaml` を書き直した。以前重複で止まっていた `2026.csv` は、同じ年のより新しい CSV があるのでスキップされる。
